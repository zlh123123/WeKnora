# Knowledge MRI 综合评估方案

本文件把课题四的“有效性验证”拆成可复现的离线评估、状态规则对照、工程性能和小规模用户试验四层。当前已完成前两层的部分版本；工程性能与用户试验列为下一轮可直接执行的协议，不能把计划中的数字写成已有结果。

## A. 知识网络质量

| 维度 | 指标 | 计算方式 | 当前证据 |
|---|---|---|---|
| 引用可解析率 | resolvable rate | 有效启用 Chunk 的引用关系 / 全部引用关系 | KB1 82/82，KB2 1243/1243 |
| 语义支持 | mapping support precision | 审核中明确支持的 Concept-Chunk 对 / 抽样对 | 18/30 = 60.0%，作者侧 AI 审核 |
| 节点覆盖 | with-reference rate | 有至少一个有效引用的 Concept / 已发布 Concept | 两库均为 100% |
| 连接集中度 | fan-out histogram、max fan-out | 每个 Chunk 被多少 Concept 引用 | 已冻结在 snapshot.json |
| 图完整性 | orphan / duplicate identity rate | identity 无当前 Wiki 页面、同名冲突数 / identity 总数 | 需要在生产库按迁移后快照执行 |

抽样必须按 KB 分层并冻结种子；不能只审核看起来正确的样本。审核记录保留失败项和理由。

## B. 题目质量

每道题同时检查四项：来源片段支持、唯一正确选项、确实测量所属 Concept、与全题库不重复。报告四项分别给出通过率，并给出四项同时通过率。补充两个指标：

- **Concept coverage**：至少有一题的 Concept 数 / 有效题目候选 Concept 数；
- **question diversity**：按事实 hash、题干相似度和来源 Chunk 分组后的有效组数 / 题目数。

生成过程需要记录：候选 Concept 数、成功生成数、JSON 校验失败数、重试次数、stale 数、冷/热命中数、p50/p95 生成耗时。当前 `quiz_items` 没有完整模型版本字段，所以这项只能从下一轮开始可靠统计。

## C. 学习状态规则对照

生成固定种子、固定用户轨迹：每个 Concept 有潜在掌握率 p，按时间产生作答；另造有暴露相关性、来源变化、重复提交和中断恢复的轨迹。固定相同轨迹比较：

1. 常数 0.5；
2. Exposure-only；
3. 最近四次原始正确率；
4. 当前产品的正确率 × evidence coverage；
5. Laplace 平滑或 Beta 后验均值。

报告 Brier、log loss、ECE、校准曲线数据和 strong/weak/uncertain 的混淆矩阵。必须分开报告 2、4、6 次作答；不能把两题 strong 当成全面掌握。再运行性质测试：

- 重放同一 idempotency key 不改变状态；
- 不同 subject、tenant、KB 互不可见；
- source hash 变化后旧 attempt 不进入当前掌握窗口；
- 中断后 resume 不跳题、不重复计数；
- 清除后的迟到 evidence 不恢复旧画像。

当前 sensitivity.json 已覆盖三种 Exposure 关系和三种作答次数，但还没有 ECE、混淆矩阵和校准曲线；因此它是第一版对照，不是完整模型评估。

## D. 工程性能

在固定 PostgreSQL、固定模型配置、固定 30/100/500 Concept 数据集上分别测：

| 场景 | 记录指标 |
|---|---|
| 个人地图首次打开 | p50/p95 API 延迟、identity 补全行数、SQL 查询数 |
| 六题冷扫描 | 总耗时、生成耗时、题库命中率、失败/重试 |
| 六题热扫描 | 总耗时、SQL 查询数、是否重复生成 |
| 两题定向复测 | 创建、恢复、提交、完成四步的 p50/p95 |
| 导出与清除 | 行数、payload 大小、事务耗时、其他 scope 是否保持 |

每个场景预热 3 次、正式测量 20 次；报告原始 JSON、环境、commit、模型配置摘要，不保存 API key。多实例锁和 SQLite 不应混在同一组结果里；分别标注数据库和部署拓扑。

## E. 小规模用户试验（可选但最有说服力）

若能找到 3–5 名试用者，把 Concept 随机分成“地图 + 推荐”与“仅地图”两组。每人先完成 5 个 Concept 的 pre-test，使用 10 分钟，再完成 post-test 和 24 小时 delayed-test。主要指标为 post-pre 分数变化、delayed retention、完成率、扫描中断率和单题耗时；记录 NASA-TLX 简化量表或 1–5 易用性评分。只报告配对原始数据、效应量和置信区间，不在小样本上做过度显著性结论。

如果没有独立用户，提交时明确写“未完成用户研究”，用 A–D 层的可复现证据支撑工程原型，不把自己的浏览器操作当作教学效果。

## 推荐的提交结论模板

“系统功能、数据隔离和状态更新通过工程验收；知识网络/题目质量由冻结样本审核；状态规则由合成轨迹对照。当前证据支持可运行和可追溯，不支持真实学习增益或掌握度校准结论。性能基准和独立用户试验需在固定部署条件下另行执行。”
