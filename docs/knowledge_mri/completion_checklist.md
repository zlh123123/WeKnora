## 1. 完成标准

- [ ] 新用户按文档完成：建库 → 导入固定文档 → Wiki 生成 → 开启学习追踪 → 带引用问答 → 个人地图 → 六题扫描 → 状态更新 → 查看证据与薄弱点 → 阅读推荐内容 → 当前知识点复测 → 刷新后状态保留。
- [ ] 用户能查看、导出、删除自己的学习画像；停用后不再记录；其他用户和租户无法越权访问。
- [ ] 真实映射和真实生成题目有抽样审核、原始记录、汇总指标及失败案例；模拟结果与真实结果分开。
- [ ] 技术文档中的每项实现、数字和效果结论可定位到代码、原始数据或验收记录。
- [ ] 最终代码版本可从干净检出运行，README、Tag、完整 SHA、submission.yaml 和成果链接齐备。

## 2. P0：完整用户流程与正确性（9 月 10 日优先）

- [ ] 固定一份小型中文知识库及源文档清单，记录来源、导入参数、Wiki 构建和模型配置，不保存凭据。
- [ ] 修复或验证旧知识库只有部分 concept identity 时的候选补全；覆盖全无、部分已有、新增 Wiki Concept 三种状态。
- [ ] 实现当前 Concept 的两题复测，复用已有扫描、判分、幂等和掌握度更新机制；不干扰已有全库扫描的恢复。
- [ ] Evidence Trail 能查看支撑判断的答题结果与来源内容；已删除或无权访问的来源给出安全提示。
- [ ] 验证推荐 → 阅读 → 定向复测 → 地图更新；没有推荐候选时解释空状态。
- [ ] 验证首次冷生成、题库复用、生成失败、可用 Concept 不足、请求超时后的恢复；错误提示提供可执行的下一步。
- [ ] 核验运行中服务、数据库和模型配置，复现并排查报告中遗留的 embedding endpoint/EOF 问题，记录实际检索是否发生回退。
- [ ] 保守统一术语：Exposure 为引用展示；strong 为通过当前验证；confidence 为作答证据量指标，不称统计置信概率。

验收证据：测试命令与结果、浏览器操作记录、相关 API/持久化状态、最终代码 SHA。预置状态只用于界面测试，不作为真实学习效果证据。

## 3. P0：隐私、生命周期与回归（9 月 10–11 日）

- [ ] 两用户、两租户及共享 KB 的读写隔离；覆盖 profile、overlay、insights、scan、attempt、export、clear。
- [ ] 导出内容完整且仅属于当前范围，不下发未答题正确答案；清除后画像、证据、作答及扫描记录符合设计。
- [ ] 停用及清除后的迟到事件不能恢复旧画像；重复提交、刷新重试不会重复计算。
- [ ] 用隔离测试数据验证 KB/tenant 删除的物理清理；明确用户退出/删除及共享权限撤销的行为。
- [ ] 验证源文档变更、题目 stale、Wiki 重建及 orphan identity 的状态与 UI 行为，避免旧验证误导用户。

## 4. P0：真实评估与可复现结果（9 月 11 日）

### A. 映射质量

- [ ] 导出 Concept 数、有可用 ChunkRefs 的比例、chunk→concept fan-out 分布、一对一/一对多比例。
- [ ] 固定抽样规则和种子，审核 20–30 个映射对，保留 concept、chunk、支持与否、理由及审核人。
- [ ] 汇总人工支持率、样本量与失败类型；旧 spike 结果仅作历史对照。

### B. 题目质量

- [ ] 抽样 30–50 道真实模型生成题，覆盖多个 Concept，保留题目、选项、标准答案、解释、source hash、来源和模型/提示词版本。
- [ ] 人工检查原文支持、唯一正确项、材料外事实、重复、无意义或过易题；保留各维度与总体通过率。
- [ ] 记录生成成功率、重试和冷/热耗时；审核不通过项不能被静默删除后再算通过率。

### C. 状态规则与预测对照

- [ ] 保留现有模拟作为 sanity check；增加 Exposure 与 latent mastery 不同相关程度的情景，说明假设。
- [ ] 对比 2/4/多轮作答下状态稳定性，报告误判 strong/weak 和 uncertain 比例，加入简单常数预测基线。
- [ ] 区分 confidence 的规则含义与预测概率，不能仅凭默认 confidence=1 的实验宣称其有效。
- [ ] 若有足够真实作答，严格用此前记录预测后续未见题目；禁止同题泄漏或把人为选定的正确/错误答案当自然用户数据。

### D. 小规模试用

- [ ] 尽量邀请 3–5 人完成同一流程，记录完成率、耗时、卡点和对证据/推荐的理解。邀请和联系由用户安排。
- [ ] 若无法招募，明确没有真实用户研究，以真实题目/映射审核加模拟完成有限验证，不宣称学习效果提升。

输出建议：`evaluation/` 下保存脱敏原始样本和审核表；脚本输出汇总；`evaluation.md` 解释指标、结果、失败案例和结论边界。

## 5. P0：技术文档与 Demo（边做边写，9 月 12 日定稿）

主文档建议：`docs/knowledge_mri/technical_report.md`，定稿后生成 PDF，按需要提供 DOCX。代码版本冻结后核对所有链接和数字。

文档目录与验收要求：

1. **问题与贡献**：课题四要求、选择的范围、已有 Wiki/Memory 能力、新增贡献；明确未接入 MemoryItem。
2. **用户流程**：从建库到复测的步骤、截图、空状态、失败恢复及画像管理。
3. **架构与数据模型**：模块关系、七张表、tenant/subject/KB 范围、个人 overlay 与公共图谱的边界。
4. **关键设计**：引用映射、歧义权重、题库生成与来源校验、确定性判分、状态阈值、扫描选择、推荐与复测。
5. **安全与生命周期**：权限、导出/清除/停用、删除、迟到事件、stale/orphan 处理。
6. **评估方法**：数据来源与规模、抽样、人工审核标准、模拟假设、基线、指标、复现命令。
7. **评估结果**：真实与模拟分表，展示失败案例、性能、样本量和不能支持的结论。
8. **工程验证与复现**：环境、模型配置、迁移、启动、测试、固定 Demo、最终版本。
9. **局限与后续工作**：两题测量的边界、题库重复使用、未覆盖的个性化能力及后续方向。
