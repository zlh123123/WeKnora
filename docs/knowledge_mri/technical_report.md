## 1. 解决什么问题

现在的知识库问答能回答问题，但用户不知道自己哪些知识只是"看过"，哪些是真的"掌握了"。

这次做的事情：在 WeKnora 的知识图谱上，给每个用户加一层学习记录。通过做题来验证是否真的掌握，而不是看过就算。

**核心思路：看过 ≠ 掌握**

- 系统给你展示一段引用 → 记录"你看过了"（接触记录）
- 你做题答对了 → 记录"你可能掌握了"（掌握证据）
- AI 只负责出题，不负责判断你懂不懂，判分是服务器做的

**交付了什么：**

- 个人知识地图（能看到自己哪些知识点学过、掌握程度如何）
- 证据时间线（每次接触、每次答题都有记录）
- 快速扫描（随机选 3 个知识点，每个出 2 道题）
- 单点复测（针对某个知识点出 2 道题）
- 推荐系统（告诉你接下来可以学什么）
- 个人数据管理（导出、清除、停用追踪）

**现状：**

目前是个能跑的原型。真实审核发现生成的题目有不少问题（题目不相关、有歧义、重复等），所以不敢说"已经验证了教学效果"。

## 3. 怎么用

**第一步：导入资料、生成 Wiki**

正常使用知识库问答。系统会自动记录你看到的引用，在个人地图上标记"接触过"。

**第二步：做题验证**

- **快速扫描**：系统选 3 个知识点，每个出 2 道题（共 6 题）
- **单点复测**：针对当前知识点出 2 道题
- 可以中途退出，下次继续做

提交答案后，系统判分并更新掌握状态。地图和证据记录会同步刷新。

**第三步：看推荐、继续学**

系统会推荐你还没掌握的相关内容。如果没有合适的推荐，不会瞎编学习路径。

**数据控制：**

- 导出：下载你的学习记录（不包含题目答案）
- 清除：删除所有学习数据
- 停用：关闭学习追踪功能

## 4. 技术架构

### 数据流程

```
文档切块 → 生成 Wiki 知识点
    ↓
用户问答看到引用 → 记录"接触过"
    ↓
系统根据知识点内容出题
    ↓
用户做题 → 服务器判分 → 更新掌握状态
    ↓
个人地图展示学习情况 + 推荐下一步
```

### 数据隔离

- **公共的**：Wiki 页面、题库（同一租户/知识库的用户共享）
- **私有的**：学习状态、做题记录、证据时间线（每个用户独立）

### 数据库表

| 表名                        | 存什么                                  |
| --------------------------- | --------------------------------------- |
| learning_profiles           | 用户是否开启学习追踪、清除时间          |
| learning_concept_identities | Wiki 页面 ID 映射（避免改名后丢失记录） |
| learning_evidence           | 所有接触记录和答题记录                  |
| user_concept_states         | 当前的掌握状态汇总                      |
| quiz_items                  | 题库（题目、答案、来源）                |
| quiz_attempts               | 做题记录                                |
| learning_scans              | 扫描进度（支持中断恢复）                |

## 5. 关键设计决策

### 5.1 看过不算掌握

问答时系统展示的引用，只能证明"你看到了"，不能证明"你读懂了"。

如果一段文本对应多个知识点，每个知识点分到的"接触权重"会被均分。

点击引用、打开 Wiki 页面这些操作都不算掌握证据，必须做题才算。

### 5.2 出题和判分

**怎么出题：**

从知识点的文本内容里，让 AI 生成四选一的选择题。

**题目检查：**

- 结构检查：4 个选项、答案在 0-3 范围内、有解释、有来源
- 不检查语义：不保证"只有一个正确答案"，不保证"题目真的测到了这个知识点"

真实审核发现的问题：
- 题目和知识点关系不大
- 多个选项都对或都不对
- 不同知识点出了重复的题

**判分逻辑：**

服务器判分，前端拿不到正确答案（防止作弊）。

### 5.3 掌握状态怎么判定

看最近 4 次答题记录：

- 答题少于 2 次 → 不确定
- 正确率 ≥ 80%（4 次对 3-4 次）→ 掌握较好
- 正确率 ≤ 40%（4 次对 0-1 次）→ 掌握较差
- 其他情况 → 不确定

**注意：**

- 2 道题全对就会判"掌握较好"，但这不等于真的完全掌握
- 题库会复用，可能记住答案了
- 没有考虑"过了一段时间会遗忘"

### 5.4 扫描和推荐

**快速扫描怎么选知识点：**

优先选你已经有学习记录的知识点，然后按这个公式排序：

```
得分 = 0.50 × (1 - 证据数量) + 0.35 × 接触次数 + 0.15 × 图谱连接数
```

不是"只选薄弱的"，已经掌握的也可能被选到。

**推荐逻辑：**

排除当前知识点和已掌握的，按掌握程度排序：掌握较差 > 不确定 > 只接触过。

规则很简单，但没有做"先修关系推理"（比如先学 A 再学 B）。

## 6. 隐私和数据管理

### 权限控制

- 必须登录才能用学习功能
- 只能看到自己的学习数据
- 导出数据时不包含题目答案（防止作弊）

### 用户操作

**停用追踪：**
关闭后不再记录新的接触和答题，但历史数据保留。

**清除数据：**
删除当前知识库的所有学习记录，不影响其他用户。记录清除时间，防止旧数据恢复。

**删除知识库/租户：**
会连带删除相关的学习数据。但多实例并发场景没有完整测试。

### 审核材料

离线导出的审核数据只包含公开教材和生成的题目，不包含：
- 用户画像
- 账户信息
- 聊天记录
- API 密钥

### 自动化测试

- 全仓库 Go 测试（包含并发测试）
- 前端 441 项测试
- 类型检查和构建

前端测试主要是代码约束检查，浏览器实际使用还需要人工验收。

### 手工验收

2026-09-10 在本机测试：

1. 做了 1 道题，提交后显示 2/2（因为之前做过 1 题）
2. 关闭页面重新打开，第二题能恢复
3. 做完后显示"掌握较好"
4. 数据库记录正确：`completed`，`current_index=2`，`total_items=2`
5. 证据时间线出现 2 条新记录
6. 原来的 6 题扫描没受影响：`pending`，`current_index=0`

**验收结论：**

功能能跑通，但这不是"学习效果测试"，只是功能测试。

### 还没测的

- 全新机器部署
- 新用户完整流程
- 所有模型失败情况的恢复
- 多实例并发

## 8. 真实数据审核

### 引用质量

冻结了 2 个知识库：
- RAG 教材：3 个文档 → 30 个知识点、82 条引用
- 视觉教材：30 个文档 → 97 个知识点、1243 条引用

每个库抽 15 条引用，人工对照原文审核：
- 18 条明确支持
- 4 条不支持
- 8 条不确定

**支持率 60%**（保守估计）

注意：这是分层抽样，不是全体引用的无偏估计。

### 题目质量

审核了全部 24 道题：

| 审核维度             | 通过数量            |
| -------------------- | ------------------- |
| 来源确实支持题目内容 | 22 / 24             |
| 只有一个正确答案     | 21 / 24             |
| 题目和知识点相关     | 21 / 24             |
| 没有重复题           | 22 / 24             |
| **四项都通过**       | **16 / 24 (66.7%)** |

**发现的问题：**

- 考环境名这种记忆题（不测理解）
- 不同知识点出了相同的题
- 缺少上下文（比如代码题没给完整代码）

**审核局限：**

- 只有作者一个人审，没有独立评审
- 没有真实用户测试
- 题目生成的模型版本没记录，无法完全复现

## 9. 模拟数据测试

### 测试设计

模拟 10000 个用户，每个人有个"真实水平" p（0 到 1 之间随机）。

做题时按 p 的概率答对（比如 p=0.8 的人有 80% 概率答对）。

测试 3 种情况：
- 接触次数和水平无关（随机）
- 接触次数和水平正相关（水平高的人多学习）
- 接触次数和水平负相关（水平低的人多学习）

### 测试结果

| 情况                      | 用"接触次数"预测 | 用"正确率"预测 | 用"正确率×证据数"预测 |
| ------------------------- | ---------------: | -------------: | --------------------: |
| 接触和水平无关，做 2 题   |           0.3286 |         0.2512 |                0.2763 |
| 接触和水平无关，做 4 题   |           0.3286 |         0.2105 |                0.2105 |
| 接触和水平正相关，做 4 题 |           0.2001 |         0.2105 |                0.2105 |

数值越小越准，0.25 是"瞎猜"的基线。

**结论：**

- 做 2 道题时，正确率预测还不如直接看接触次数
- 当前判"掌握较好"的人里，有 50.2% 的真实水平低于 80%

**意思是：**

2 道题判定不太准，但目前就是这么设计的。测试了 Laplace 平滑（一种统计方法）效果更好，但还没实装。

模拟结果不能直接说明真实效果。
